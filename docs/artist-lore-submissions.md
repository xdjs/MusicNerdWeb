# Lore URL suggestions

The artist page has two link flows. **Add a link** submits a supported profile-service URL through the UGC queue, where ordinary accounts wait for admin review. **Suggest a Lore source** accepts a public article, interview, review, or other source URL from a signed-in account. It creates a pending `artist_vault_sources` row; the source stays off the public Lore carousel until an approved claimant or admin approves it in edit mode. For a claimed profile, the confirmation says it is pending artist review. For an unclaimed profile such as Bike Lane, it explains that an admin can review the source until the artist claims it.

The public Lore section shows a single **Suggest a Lore source** button. Signed-out visitors reach login from that button; signed-in visitors enter the URL in a dialog styled like the profile-link dialog. Validation, submission feedback, and the review explanation stay inside the dialog. A successful submission clears the URL so another source can be suggested without reopening it. Closing and reopening starts a fresh form. Artist owners and admins keep the separate **Add to Lore** edit-mode entry point.

An artist owner or admin can enter Lore edit mode from the section itself, add more source URLs, and approve or reject pending sources. An admin can edit any artist profile, subject to the account's `users.is_admin` flag. The shared source insertion helper strips URL fragments and serializes public URLs for every writer, including onboarding. Visitor and editor submissions also compare older stored URLs by that form before insertion, reading only the URL column. Duplicate sources return an already-suggested message. The API validates public HTTP(S) URLs server-side and uses the existing `/api` request rate limit. Visitor submissions and approval save the URL without fetching it. Approved URL-only suggestions appear with a domain-based title; richer extraction requires a separate durable job with network destination checks.

The Admin dashboard has a separate **Lore review** section beside profile-link submissions. It lists pending Lore sources across artists, newest first, with server-side artist/URL search and pagination. The dashboard badge counts all pending Lore while the result summary counts the current search matches. Admins can open the source and artist profile, then approve or reject through the same authorized source-status action used in artist edit mode. Admin review updates a row only if it is still pending, so a stale queue cannot overwrite another reviewer's decision. The queue includes all pending sources and now distinguishes human submissions, uploads, research discoveries, and unknown legacy origins. Cards show the initiating account and trigger when recorded, along with current claim state. Origin/claim filters combine with artist, source, or contributor search. The Admin Activity section links research requests and source review to their initiating accounts. See [provenance and migration](lore-provenance.md); historical rows are not backfilled from ownership or timestamps.
